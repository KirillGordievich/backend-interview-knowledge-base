# Python — Asyncio: Вопросы

> Теория: [async.md](async.md)

---

**Q: Что такое корутина (coroutine) в Python?**

Функция, определённая через `async def`. При вызове возвращает объект корутины, а не результат. Для запуска нужно `await` или передать в event loop. Корутина приостанавливается на `await` и возвращает управление event loop'у.

```python
async def fetch():
    return 42

coro = fetch()   # объект корутины, код НЕ выполнился
result = await coro  # теперь выполнился → 42
```

---

**Q: Что такое event loop и как он работает?**

Event loop — центральный механизм asyncio. Это бесконечный цикл, который:
1. Берёт готовые к выполнению корутины из очереди
2. Выполняет их до следующего `await`
3. Когда корутина ждёт I/O — переключается на другую
4. Когда I/O готов — возвращает корутину в очередь

Запуск: `asyncio.run(main())`. В одном потоке — один event loop.

---

**Q: Чем `await` отличается от обычного вызова функции?**

`await` приостанавливает текущую корутину и отдаёт управление event loop'у. Обычный вызов блокирует весь поток. `await` можно использовать только внутри `async def` и только с awaitable-объектами (корутины, Task, Future).

---

**Q: В чём разница между `asyncio.create_task()` и `await`?**

- `await coro()` — последовательное выполнение: текущая корутина ждёт завершения
- `asyncio.create_task(coro())` — создаёт Task, который планируется event loop'ом параллельно (конкурентно) с другими задачами

```python
# Последовательно — 2 секунды
await fetch(1)
await fetch(2)

# Конкурентно — 1 секунда
t1 = asyncio.create_task(fetch(1))
t2 = asyncio.create_task(fetch(2))
await t1
await t2
```

---

**Q: Что такое `asyncio.gather()` и когда его использовать?**

Запускает несколько корутин конкурентно и ждёт завершения всех. Возвращает список результатов в порядке передачи. Удобно когда нужно дождаться группы задач.

```python
results = await asyncio.gather(fetch(1), fetch(2), fetch(3))
```

С `return_exceptions=True` — исключения возвращаются как значения, а не прерывают gather.

---

**Q: `asyncio.gather()` vs `asyncio.wait()` vs `asyncio.TaskGroup` — когда что?**

- `gather` — простой случай: запустить всё, получить все результаты. Если одна упала — по умолчанию всё падает
- `wait` — тонкий контроль: можно ждать первого завершения (`FIRST_COMPLETED`), обрабатывать done/pending
- `TaskGroup` (Python 3.11+) — структурированная конкурентность: все задачи отменяются при ошибке, нельзя "забыть" задачу

---

**Q: Что произойдёт если вызвать блокирующую функцию (time.sleep, requests.get) внутри async-кода?**

Заблокирует весь event loop — все остальные корутины встанут. Нужно использовать `asyncio.to_thread()` или `loop.run_in_executor()` для запуска блокирующего кода в отдельном потоке.

```python
# Плохо
await asyncio.sleep(0)
time.sleep(5)  # блокирует event loop на 5 сек

# Хорошо
await asyncio.to_thread(time.sleep, 5)
```

---

**Q: Что такое `asyncio.to_thread()` и когда он нужен?**

Запускает синхронную (блокирующую) функцию в отдельном потоке из пула, не блокируя event loop. Нужен для: файлового I/O, CPU-bound операций, вызова синхронных библиотек (requests, psycopg2) из async-кода.

---

**Q: Какие примитивы синхронизации есть в asyncio?**

- `asyncio.Lock` — мьютекс, один доступ к ресурсу
- `asyncio.Semaphore` — ограничивает число одновременных доступов (например, лимит запросов)
- `asyncio.Event` — сигнал между корутинами (set/wait)
- `asyncio.Queue` — очередь для передачи данных между корутинами (producer-consumer)

Все они **НЕ потокобезопасны** — работают только внутри одного event loop'а.

---

**Q: Зачем нужен `asyncio.Semaphore`?**

Ограничение конкурентности. Например, не делать больше 10 HTTP-запросов одновременно:

```python
sem = asyncio.Semaphore(10)

async def fetch(url):
    async with sem:  # максимум 10 одновременно
        return await client.get(url)
```

---

**Q: Что такое `async with` и `async for`?**

- `async with` — асинхронный контекстный менеджер (методы `__aenter__` / `__aexit__`). Для ресурсов с асинхронной инициализацией/очисткой.
- `async for` — асинхронная итерация (методы `__aiter__` / `__anext__`). Для потоковых данных из асинхронных источников.

---

**Q: Можно ли использовать `asyncio.Lock` из обычного threading?**

Нет. Примитивы asyncio работают только в контексте event loop'а и не потокобезопасны. Для межпоточной синхронизации нужны `threading.Lock` и т.д.

---

**Q: Что такое uvloop?**

Drop-in замена стандартного event loop на реализацию на основе libuv (C-библиотека из Node.js). В 2-4 раза быстрее стандартного asyncio event loop.

---

**Q: asyncio — это параллельность или конкурентность?**

Конкурентность (concurrency), не параллельность (parallelism). Всё выполняется в одном потоке, задачи переключаются на точках `await`. Для CPU-bound задач asyncio не даёт ускорения — нужен multiprocessing.

---

**Q: Что такое structured concurrency и TaskGroup?**

Structured concurrency — паттерн, при котором время жизни дочерних задач привязано к родительскому scope. `TaskGroup` (Python 3.11+) реализует это: все задачи гарантированно завершаются при выходе из блока `async with`, при ошибке в одной задаче — все остальные отменяются.

```python
async with asyncio.TaskGroup() as tg:
    tg.create_task(fetch(1))
    tg.create_task(fetch(2))
# Здесь все задачи гарантированно завершены
```

---

**Q: Как отменить задачу в asyncio?**

`task.cancel()` — устанавливает флаг отмены. При следующем `await` внутри задачи выбрасывается `CancelledError`. Задача может перехватить `CancelledError` для cleanup, но должна повторно его выбросить (или завершиться).
