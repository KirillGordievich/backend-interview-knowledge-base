# Python — Internals: Вопросы

> Теория: [internals.md](internals.md)

---

**Q: Как работает управление памятью в CPython?**

Три уровня:
1. **Подсчёт ссылок (reference counting)** — основной механизм. У каждого объекта есть счётчик ссылок. Когда счётчик падает до 0 — объект удаляется немедленно.
2. **Garbage collector** — для циклических ссылок, которые reference counting не может разрешить.
3. **Аллокатор pymalloc** — пул малых объектов (< 512 байт), чтобы не дёргать системный `malloc` на каждый мелкий объект.

---

**Q: Что такое подсчёт ссылок и когда объект удаляется?**

Каждый объект хранит `ob_refcnt` — количество ссылок на него. Ссылка увеличивается при присваивании, передаче в функцию, добавлении в коллекцию. Уменьшается при `del`, выходе из scope, перезаписи переменной. Когда `ob_refcnt == 0` — объект удаляется сразу.

```python
import sys
a = [1, 2, 3]
sys.getrefcount(a)  # 2 (a + временная ссылка в getrefcount)
```

---

**Q: Зачем нужен garbage collector если есть reference counting?**

Reference counting не справляется с циклическими ссылками:

```python
a = []
b = []
a.append(b)
b.append(a)
del a, b
# refcount обоих > 0, но объекты недостижимы — утечка памяти!
```

GC обнаруживает и удаляет такие циклы. Работает поколенчески (3 поколения).

---

**Q: Как работает поколенческий (generational) GC?**

Три поколения: 0 (молодые), 1, 2 (старые). Новые объекты попадают в поколение 0. Если объект пережил сборку — переходит в следующее поколение. Молодые поколения собираются чаще (гипотеза: большинство объектов умирают молодыми).

---

**Q: Что такое `PyObject` в CPython?**

Базовая C-структура для всех Python объектов. Содержит минимум: `ob_refcnt` (счётчик ссылок) и `ob_type` (указатель на тип). Все Python объекты — это `PyObject*` в C.

---

**Q: Как устроен `dict` в CPython?**

Хеш-таблица с открытой адресацией. Хеш ключа → индекс в таблице. При коллизии — пробирование (probing). С Python 3.6+ использует compact dict: отдельный массив индексов + упорядоченный массив записей (key, value, hash) — экономит память и сохраняет порядок вставки.

---

**Q: Что такое коллизия хешей и как dict с ней справляется?**

Коллизия — когда разные ключи дают одинаковый хеш (или одинаковый индекс в таблице). CPython использует открытую адресацию: ищет следующий свободный слот по формуле пробирования. Поэтому O(1) — это среднее, а O(n) — худший случай.

---

**Q: Что такое `__hash__` и `__eq__` и как они связаны?**

Для работы в `dict`/`set` объект должен быть hashable: иметь `__hash__` и `__eq__`. Правило: если `a == b`, то `hash(a) == hash(b)` (обратное не обязательно). Если переопределяешь `__eq__` — нужно переопределить и `__hash__`.

---

**Q: Что такое интернирование (interning) в CPython?**

CPython кэширует часто используемые объекты:
- Малые целые числа от -5 до 256 — заранее созданы и переиспользуются
- Короткие строки и строки-идентификаторы

```python
a = 256
b = 256
a is b  # True — один объект

a = 257
b = 257
a is b  # False (может быть True в REPL, но не гарантировано)
```

---

**Q: Как работает `list` внутри CPython?**

Динамический массив указателей на `PyObject*`. При `append` когда массив полон — перевыделяется с запасом (over-allocation). Формула роста: ~1.125x. Поэтому `append` — O(1) амортизированно, а `insert(0)` — O(n) из-за сдвига элементов.

---

**Q: Как работают генераторы внутри CPython?**

Генератор — это замороженный фрейм выполнения. При `yield` состояние (локальные переменные, позиция в байткоде) сохраняется в объекте генератора. При `next()` — фрейм восстанавливается и выполнение продолжается с точки yield.

---

**Q: Что такое `type` как метакласс?**

`type` — метакласс по умолчанию. Классы — это экземпляры `type`. `type(MyClass)` → `<class 'type'>`. `type('MyClass', (Base,), {'attr': 1})` — динамическое создание класса.

```python
class Foo: pass
type(Foo)        # <class 'type'>
type(type)       # <class 'type'> — type является своим же экземпляром
isinstance(Foo, type)  # True
```

---

**Q: Что такое `__del__` и почему его не стоит использовать?**

Финализатор — вызывается когда объект уничтожается. Проблемы: неопределённое время вызова, может задержать сборку циклических ссылок, исключения в `__del__` игнорируются. Используй контекстные менеджеры (`with`) вместо `__del__`.

---

**Q: Что такое `__sizeof__` и `sys.getsizeof`?**

`sys.getsizeof(obj)` — размер объекта в байтах (без учёта объектов, на которые он ссылается). Вызывает `obj.__sizeof__()` + добавляет overhead GC. Для глубокого подсчёта нужны сторонние инструменты.

---

**Q: Почему `set` быстрее `list` для проверки `in`?**

`set` использует хеш-таблицу: `x in set` — O(1) в среднем (вычислить хеш, проверить слот). `x in list` — O(n) (линейный перебор). Для частых проверок принадлежности всегда используй `set`.
