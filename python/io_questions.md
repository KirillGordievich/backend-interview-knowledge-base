# Python — I/O: Вопросы

> Теория: [io.md](io.md)

---

**Q: Как правильно открывать файлы в Python?**

Через контекстный менеджер `with` — гарантирует закрытие файла даже при исключении:

```python
with open('file.txt', 'r', encoding='utf-8') as f:
    data = f.read()
# файл автоматически закрыт
```

---

**Q: Какие режимы открытия файла существуют?**

- `'r'` — чтение (по умолчанию), файл должен существовать
- `'w'` — запись, создаёт/перезаписывает файл
- `'a'` — дозапись в конец
- `'x'` — эксклюзивное создание, ошибка если файл существует
- `'b'` — бинарный режим (`'rb'`, `'wb'`)
- `'t'` — текстовый режим (по умолчанию)
- `'+'` — чтение и запись (`'r+'`, `'w+'`)

---

**Q: `read()` vs `readline()` vs `readlines()` — в чём разница?**

- `read()` — читает весь файл в строку (или `read(n)` — n символов)
- `readline()` — одна строка
- `readlines()` — все строки в список

Для больших файлов лучше итерировать: `for line in f:` — читает по одной строке, экономит память.

---

**Q: Что такое `seek()` и `tell()`?**

- `tell()` — текущая позиция курсора в файле (в байтах)
- `seek(offset, whence)` — переместить курсор. `whence`: 0 — от начала, 1 — от текущей позиции, 2 — от конца

```python
f.seek(0)       # перемотать в начало
f.seek(0, 2)    # перемотать в конец
pos = f.tell()  # текущая позиция
```

---

**Q: Чем отличается текстовый и бинарный режим?**

- Текстовый (`'r'`/`'w'`) — возвращает `str`, автоматическая конвертация переносов строк и кодировки
- Бинарный (`'rb'`/`'wb'`) — возвращает `bytes`, данные как есть без преобразований

Для изображений, архивов, бинарных протоколов — всегда бинарный.

---

**Q: Что такое `StringIO` и `BytesIO`?**

Файлоподобные объекты в памяти:
- `io.StringIO` — "файл" для строк (`str`)
- `io.BytesIO` — "файл" для байтов (`bytes`)

Полезно для тестирования, работы с библиотеками, которые ожидают файловый объект, буферизации.

```python
from io import StringIO
buf = StringIO()
buf.write('hello')
buf.getvalue()  # 'hello'
```

---

**Q: Зачем указывать `encoding='utf-8'` при открытии файла?**

Кодировка по умолчанию зависит от ОС (`locale.getpreferredencoding()`). На Windows это может быть `cp1251` или `cp1252`, а не UTF-8. Явное указание `encoding='utf-8'` гарантирует одинаковое поведение на всех платформах.

**Q: Как сериализовать данные в JSON?**

```python
import json

# dict/list → JSON строка
json.dumps({'key': 'value'})

# JSON строка → dict/list
json.loads('{"key": "value"}')

# Запись/чтение из файла
json.dump(data, file)
json.load(file)
```

JSON поддерживает: str, int, float, bool, None, list, dict. Для datetime, set и т.д. нужен кастомный encoder.

---

**Q: `json.dumps` vs `json.dump` — в чём разница?**

- `json.dumps(obj)` — сериализует в строку (`str`)
- `json.dump(obj, file)` — сериализует прямо в файл

Аналогично: `json.loads(str)` vs `json.load(file)`.

---

**Q: Что такое `pickle` и чем отличается от JSON?**

`pickle` — бинарная сериализация Python объектов. Может сериализовать почти любой Python объект (классы, функции, замыкания). JSON — текстовый, кроссплатформенный, ограниченный набор типов.

**Важно:** никогда не загружай pickle из ненадёжного источника — может исполнить произвольный код.

---

**Q: Когда использовать `pickle` vs `json`?**

- **JSON** — обмен данными между системами, API, конфиги, человекочитаемость
- **pickle** — кэширование Python объектов, ML модели, внутреннее хранение (только если доверяешь источнику)
