# Фундаментальные концепции

## Статическая vs Динамическая типизация

| | Статическая | Динамическая |
|---|---|---|
| Когда проверяются типы | При компиляции/анализе | При выполнении |
| Объявление типов | Обязательно | Не требуется |
| Ошибки типов | До запуска | Во время выполнения |
| Примеры | C, Java, Go, Rust, C# | Python, JavaScript, Ruby |

**Статически типизированные:** компилятор проверяет типы до запуска — ошибки типов невозможны в рантайме.

**Динамически типизированные:** тип переменной определяется значением в момент присвоения. Гибче, но ошибки типов обнаруживаются позже — при выполнении.

Python — динамически типизированный язык с **опциональными** аннотациями типов. Аннотации проверяются статическими анализаторами (mypy, Pyright), но не интерпретатором.

```python
x = 42        # тип int определяется при выполнении
x = "hello"   # и сразу может стать str — Python не запрещает

# С аннотациями: mypy проверяет ДО запуска
def add(a: int, b: int) -> int:
    return a + b

add("x", 1)   # mypy: error — но Python запустит без ошибки
```

## Биты и байты

**Bit** (BInary digiT) — минимальная единица информации: 0 или 1.

| Единица | Размер |
|---|---|
| bit | 1 бит |
| byte (байт) | 8 бит |
| KB | 1024 байт |
| MB | 1024 КБ |
| GB | 1024 МБ |
| TB | 1024 ГБ |

**Размеры числовых типов:**
```
bool:    1 bit  (в CPython хранится как int — 28 байт из-за объекта)
int8:    8 bit  → −128 до 127
int16:  16 bit  → −32 768 до 32 767
int32:  32 bit  → ≈ ±2.1 млрд
int64:  64 bit  → ≈ ±9.2 × 10^18
float32: 32 bit → одинарная точность (~7 значимых цифр)
float64: 64 bit → двойная точность (~15 значимых цифр)
```

Python `int` — произвольной точности (bignums), занимает от 28 байт + ~4 байта на каждые 30 бит числа.

## Безопасность доступа к памяти

Концепция предотвращения ошибок при работе с памятью, ведущих к уязвимостям и крашам.

**Типичные проблемы в небезопасном коде (C/C++):**
- **Buffer overflow** — запись за пределы буфера → перезапись чужой памяти → RCE-уязвимость
- **Dangling pointer** — указатель на освобождённую память
- **Use-after-free** — использование объекта после удаления
- **Double free** — двойное освобождение памяти

**Как языки решают:**

| Язык | Подход к безопасности памяти |
|---|---|
| C/C++ | Ручное управление — нет защиты, максимальная производительность |
| Java, Python, Go | GC — автоматическое управление, безопасно, некоторый overhead |
| Rust | Ownership system — компилятор гарантирует безопасность без GC |

Python безопасен по памяти: CPython управляет всеми объектами через reference counting + GC. Прямой доступ к памяти невозможен без C-расширений.

## ETL (Extract, Transform, Load)

Трёхэтапный процесс переноса данных из источников в хранилище данных (DWH):

1. **Extract** — извлечение из источников (PostgreSQL, S3, API, Kafka, файлы)
2. **Transform** — очистка, агрегация, преобразование формата
3. **Load** — загрузка в целевое хранилище (Data Warehouse, Data Lake)

```python
def etl_daily_orders():
    # Extract
    raw_orders = source_db.execute(
        "SELECT * FROM orders WHERE created_at::date = CURRENT_DATE - 1"
    )

    # Transform
    facts = [
        {
            "date": row.created_at.date(),
            "product_id": row.product_id,
            "revenue": row.quantity * row.price,
            "region": normalize_region(row.shipping_country),
        }
        for row in raw_orders
        if row.status == "completed"
    ]

    # Load
    warehouse.bulk_insert("fact_daily_sales", facts)
```

**Инструменты:** Apache Airflow, dbt, Prefect, Luigi.

## ООП vs Функциональное программирование

Два разных подхода к организации кода. ООП строит программу как набор объектов с состоянием и поведением, FP — как набор чистых функций без изменяемого состояния.

**ООП (Object-Oriented Programming):**
- Данные и методы упакованы в объект
- Объекты хранят состояние и меняют его
- Взаимодействие через методы и наследование

```python
class BankAccount:
    def __init__(self, balance):
        self.balance = balance  # изменяемое состояние

    def deposit(self, amount):
        self.balance += amount  # меняем объект
```

**FP (Functional Programming):**
- Функции принимают данные и возвращают новые данные — не меняют исходное
- Нет побочных эффектов (side effects): одни и те же аргументы → всегда один результат
- Вместо циклов и мутаций — `map`, `filter`, `reduce`

```python
# Чистая функция: не трогает исходный список
def add_bonus(employees, bonus):
    return [
        {**emp, "salary": emp["salary"] + bonus}
        for emp in employees
    ]

# Тот же вызов всегда даёт тот же результат
result1 = add_bonus(employees, 1000)
result2 = add_bonus(employees, 1000)  # result1 == result2
```

| | ООП | FP |
|---|---|---|
| Состояние | Изменяемое, внутри объекта | Иммутабельное, функции возвращают новые данные |
| Основная единица | Класс/объект | Функция |
| Побочные эффекты | Допустимы | Избегаются (чистые функции) |
| Подходит для | Сложные сущности с поведением (User, Order) | Трансформации данных, пайплайны |

**Где что применяют:** большинство современных языков поддерживают оба подхода. Python, JavaScript, Kotlin — мультипарадигмальные: можно писать ООП-код, FP-код или смешивать.

На практике в бекенде:
- ООП — сервисы, репозитории, модели данных
- FP — обработка данных, бизнес-логика без состояния (`map/filter/reduce`, list comprehensions)

## DevOps

Концепция, объединяющая разработку (Dev) и операционную деятельность (Ops) для ускорения поставки программного обеспечения.

**Ключевые практики:**
- **CI/CD** — автоматическая сборка, тестирование и деплой
- **Infrastructure as Code** — инфраструктура описывается кодом (Terraform, Ansible)
- **Мониторинг** — наблюдаемость как часть разработки
- **Containerization** — Docker, Kubernetes
- **Культура** — общая ответственность за продукт между Dev и Ops

**Цель:** сократить время от написания кода до его появления у пользователя (lead time), обеспечить надёжность и быстрое восстановление при сбоях (MTTR).
