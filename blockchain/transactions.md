# Blockchain — Транзакции и Mempool

## Структура транзакции

**Транзакция** — подписанная инструкция от EOA (кошелька) на выполнение действия: перевод ETH, вызов смарт-контракта, деплой контракта.

```ts
// Поля транзакции Ethereum
{
    nonce:                  5,          // порядковый номер tx от этого адреса
    to:                     "0xABC...", // адрес получателя (null при деплое)
    value:                  "1000000000000000000",  // 1 ETH в Wei
    data:                   "0xa9059cbb...",         // calldata (для смарт-контрактов)
    gasLimit:               21000,      // максимум газа
    maxFeePerGas:           "30",       // Gwei
    maxPriorityFeePerGas:   "2",        // Gwei (tip валидатору)
    chainId:                1,          // защита от replay attacks между сетями
    // подпись (v, r, s) — ECDSA
    v: "0x1",
    r: "0x...",
    s: "0x...",
}
```

**Nonce** — критически важен: транзакции от одного адреса обрабатываются строго по возрастанию nonce. Пропуск в nonce = все следующие транзакции висят в pending.

## Жизненный цикл транзакции

```
1. Создание и подпись
   │  Пользователь формирует tx, подписывает приватным ключом
   ▼
2. Broadcast в сеть
   │  Отправка через RPC-ноду (MetaMask → Infura/Alchemy → P2P-сеть)
   ▼
3. Mempool (pending)
   │  Ноды проверяют: подпись, nonce, баланс, gas price
   │  Tx попадает в пул ожидания — виден всем участникам сети
   ▼
4. Выбор block builder'ом
   │  Builder сканирует mempool, выбирает транзакции
   │  Приоритет: gas price + MEV-возможности
   ▼
5. Сборка блока
   │  Builder симулирует исполнение в EVM
   │  Упаковывает tx в блок, добавляет заголовок
   ▼
6. Предложение валидатору (proposer)
   │  Через relay (MEV-Boost): аукцион между builders
   │  Proposer выбирает самый ценный блок
   ▼
7. Attestation (голосование)
   │  Другие валидаторы проверяют и голосуют за блок
   │  >2/3 attesters → блок принят
   ▼
8. Finality
      ~32 блока (~6.4 минуты) → экономическая финальность
      После этого откат практически невозможен
```

## Mempool

**Mempool (memory pool)** — глобальный пул неподтверждённых транзакций, хранящийся на каждой полной ноде.

**Как работает:**
- Каждая нода поддерживает свой mempool (не синхронизирован глобально)
- Транзакции распространяются по P2P gossip-протоколу
- Ноды валидируют перед добавлением: правильная подпись, достаточный баланс, корректный nonce

**Приоритизация:**
```
Priority = baseFee + priorityFee (tip)
```
Транзакции с более высоким tip выбираются первыми.

**Замена транзакции (Replace-by-Fee, RBF):**
```
Если tx завязла → отправь новую с тем же nonce, но gas price ≥ старый × 1.1
```

**Eviction (вытеснение):**
- Mempool ограничен по размеру (~5000 tx в geth по умолчанию)
- Самые дешёвые транзакции вытесняются при переполнении
- Старые tx с нулевым шансом включения отбрасываются

## Proposer-Builder Separation (PBS)

До PBS валидаторы сами строили блоки → у них были огромные возможности для MEV-манипуляций.

**PBS разделяет роли:**

```
┌─────────────┐     ┌──────────┐     ┌────────────┐
│   Builder   │────►│  Relay   │────►│  Proposer  │
│ (строит блок│     │(посредник│     │(валидатор, │
│  из mempool)│     │ + аудит) │     │  подписывает│
└─────────────┘     └──────────┘     └────────────┘
```

- **Builder** — специализируется на сборке максимально ценных блоков
- **Relay** — доверенный посредник, принимает блоки от builders, показывает headers proposer'у (без тела блока — защита от кражи MEV)
- **Proposer** — выбирает лучший header по ценности, подписывает commitment, получает тело блока и включает его в блокчейн

**MEV-Boost** — реализация PBS для Ethereum (используется ~90% валидаторов).

## MEV (Maximal Extractable Value)

**MEV** — прибыль, которую можно извлечь через упорядочивание, включение или исключение транзакций в блоке.

**Источники MEV:**

| Тип | Описание | Пример |
|---|---|---|
| **Arbitrage** | Разница цен между DEX'ами | Купить на Uniswap, продать на Sushiswap |
| **Sandwich attack** | Оборачивание большой tx двумя своими | Front-run + back-run жертвы |
| **Liquidations** | Первым ликвидировать позицию | Протоколы типа Aave, Compound |
| **NFT mint** | Первым купить редкий NFT | Free mint'ы |

**Sandwich attack:**
```
1. Searcher видит большую swap-tx в mempool
2. Front-run: купить токен ПЕРЕД жертвой (повышает цену)
3. Жертва делает swap по худшей цене (slippage)
4. Back-run: продать токен ПОСЛЕ жертвы (фиксирует прибыль)
```

**Flashbots** — экосистема для цивилизованного MEV: searchers → builders → relays → proposers. Уменьшает газовые войны и gas price спайки.

## Типы нод

| Тип | Что хранит | Использование |
|---|---|---|
| **Full node** | Все блоки + текущее состояние | Валидация, RPC-запросы |
| **Archive node** | Всё + историческое состояние | `eth_call` на старых блоках, аналитика |
| **Light node** | Только заголовки блоков | Мобильные кошельки |
| **Validator node** | Full node + стейкинг 32 ETH | Предложение и аттестация блоков |

## RPC и провайдеры

Взаимодействие с блокчейном через JSON-RPC API:

```ts
// Infura / Alchemy / QuickNode — hosted RPC
const provider = new ethers.JsonRpcProvider(
    `https://mainnet.infura.io/v3/${INFURA_KEY}`
);

// Ключевые методы
await provider.getBlockNumber();                     // текущий блок
await provider.getBalance(address);                  // баланс в Wei
await provider.getTransactionReceipt(txHash);        // результат tx
await provider.getLogs({ address, topics, fromBlock }); // события

// WebSocket — для подписок
const wsProvider = new ethers.WebSocketProvider(WS_URL);
wsProvider.on('block', (blockNumber) => {
    console.log('New block:', blockNumber);
});
```

**Популярные провайдеры:** Infura, Alchemy, QuickNode, Ankr, публичные RPC (chainlist.org).
