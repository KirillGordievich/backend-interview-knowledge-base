# Linux — Сеть

## Сокет (Socket)

Сокет — конечная точка сетевого соединения: комбинация IP-адреса и порта (`192.168.1.1:8080`). Файловый дескриптор, через который процесс отправляет и получает данные.

**Типы:**
- TCP-сокет — надёжное соединение с установлением связи
- UDP-сокет — без установления соединения, без гарантий доставки
- Unix domain socket — для IPC (межпроцессного взаимодействия) через файл на диске

---

## Адреса и порты

### localhost / 127.0.0.1

Loopback-адрес — только эта машина. Трафик не покидает сетевой стек. Используется для локальной разработки и общения процессов на одном хосте.

### 0.0.0.0

**Специальный адрес**: означает «все сетевые интерфейсы». Когда сервер слушает `0.0.0.0:8080` — он принимает соединения на любом интерфейсе (localhost, eth0, wifi...).

| Адрес | Смысл |
|---|---|
| `127.0.0.1` | Только loopback (локальная машина) |
| `0.0.0.0` | Все интерфейсы (снаружи и внутри) |
| `192.168.1.x` | Конкретный сетевой интерфейс |

### Порты

16-битное число (0–65535):
- **0–1023** — well-known (требуют root): HTTP 80, HTTPS 443, SSH 22, PostgreSQL 5432
- **1024–49151** — registered (обычные приложения)
- **49152–65535** — ephemeral (клиентские порты, назначаются ОС)

## Просмотр открытых портов

```bash
# ss — современная замена netstat (быстрее)
ss -tlnp           # TCP, слушающие, числа, процессы
ss -ulnp           # UDP
ss -tlnp | grep :8080   # конкретный порт

# netstat (устаревший, но ещё встречается)
netstat -tlnp

# lsof — список открытых файлов/сокетов
lsof -i            # все сетевые подключения
lsof -i :8080      # кто слушает порт 8080
lsof -i TCP        # только TCP

# Найти процесс занимающий порт
ss -tlnp | grep 8080
lsof -i :8080
fuser 8080/tcp     # только PID
```

**ss vs netstat:** `ss` читает данные напрямую из ядра через netlink, работает быстрее. `netstat` читает `/proc/net/*`. На современных системах предпочтительнее `ss`.

## DNS

DNS (Domain Name System) — переводит доменное имя в IP-адрес.

```bash
nslookup google.com       # простой DNS-запрос
dig google.com            # детальный DNS-запрос
dig google.com +short     # только IP
host google.com           # краткий результат

cat /etc/hosts            # локальные переопределения DNS
cat /etc/resolv.conf      # настройки DNS-серверов
```

---

## Что происходит после `curl google.com`

1. **DNS-резолвинг**: `curl` запрашивает IP для `google.com` у DNS-сервера из `/etc/resolv.conf`
2. **TCP handshake**: установление TCP-соединения с IP:80 (SYN → SYN-ACK → ACK)
3. **HTTP запрос**: `curl` отправляет `GET / HTTP/1.1\r\nHost: google.com\r\n\r\n`
4. **Обработка редиректа**: Google возвращает `301 Moved Permanently → https://www.google.com`
5. **TLS handshake**: согласование шифрования
6. **HTTP ответ**: сервер возвращает HTML
7. **Закрытие соединения**: TCP FIN handshake

```bash
curl -v google.com        # verbose — показать весь процесс
curl -I google.com        # только заголовки ответа
curl -L google.com        # следовать редиректам
```

## Диагностика сети

```bash
ping 8.8.8.8              # проверить доступность (ICMP)
ping -c 4 google.com      # 4 пакета

traceroute google.com     # маршрут пакетов до хоста
mtr google.com            # traceroute в реальном времени

# Проверить firewall
iptables -L -n -v         # все правила
ufw status                # Ubuntu

# Мониторинг трафика
tcpdump -i eth0 port 80   # захват трафика на порту 80
tcpdump -i any -n         # весь трафик без DNS-резолвинга
```

## iptables

Механизм фильтрации сетевых пакетов в Linux (firewall).

```bash
iptables -L                                       # список правил
iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # разрешить SSH
iptables -A INPUT -j DROP                         # запретить всё остальное
iptables -D INPUT -j DROP                         # удалить правило
```

В большинстве дистрибутивов управляется через `ufw` (Ubuntu) или `firewalld` (RHEL/CentOS).
