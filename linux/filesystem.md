# Linux — Файловая система

## Inode

Inode (index node) — структура данных, хранящая метаданные файла. Каждый файл имеет один inode.

**Что хранится в inode:**
- Тип файла (обычный, директория, symlink, устройство...)
- Права доступа (permissions)
- Владелец (UID) и группа (GID)
- Размер файла
- Временны́е метки: создание, изменение, последний доступ
- Счётчик жёстких ссылок (link count)
- Указатели на блоки данных на диске

**Что НЕ хранится в inode:**
- Имя файла — оно хранится в директории (директория = таблица "имя → номер inode")

```bash
ls -i file.txt         # показать номер inode
stat file.txt          # полная информация об inode
df -i                  # использование inodes
```

**Почему имя не в inode?** Это позволяет нескольким именам ссылаться на один и тот же inode — жёсткие ссылки.

## Жёсткие и символьные ссылки

### Hard link (жёсткая ссылка)

Ещё одно имя для того же inode. Указывает на те же данные.

```bash
ln file.txt hardlink.txt

ls -i file.txt hardlink.txt
# 12345 file.txt
# 12345 hardlink.txt  ← одинаковый inode!
```

- Удаление одного имени не удаляет данные — только уменьшает link count
- Данные реально удаляются, когда link count = 0 **и** ни один процесс не держит файл открытым
- Нельзя создать hard link на директорию (защита от циклов)
- Нельзя создать hard link на другой файловой системе

### Symbolic link (симлинк, мягкая ссылка)

Отдельный файл, содержащий путь к цели. Аналог ярлыка в Windows.

```bash
ln -s /path/to/target symlink.txt
ls -la symlink.txt
# lrwxrwxrwx 1 user group 18 Jan 1 symlink.txt -> /path/to/target
```

- Может указывать на директорию
- Может указывать на другую файловую систему
- Если цель удалена — симлинк «битый» (dangling symlink)
- Имеет собственный inode

### Сравнение

| | Hard link | Symbolic link |
|---|---|---|
| Собственный inode | Нет (общий с целью) | Да |
| Ссылка на директорию | Нельзя | Можно |
| Другая файловая система | Нельзя | Можно |
| Работает после удаления цели | Да | Нет (битый) |

---

## Что происходит при rm

`rm` уменьшает link count inode на 1.

- Если link count > 0 → данные остаются (есть другие hard links)
- Если link count = 0 **и** файл не открыт ни одним процессом → блоки данных освобождаются
- Если link count = 0, **но** файл открыт → блоки освобождаются только после закрытия файла

```bash
# Пример: log-файл удалили, но место не освободилось
# → сервис ещё держит файл открытым
lsof | grep deleted    # найти удалённые, но открытые файлы
```

## Структура директорий Linux

| Путь | Содержимое |
|---|---|
| `/` | Корневая директория |
| `/etc` | Конфигурационные файлы системы (nginx.conf, passwd, hosts) |
| `/var` | Изменяемые данные: логи (`/var/log`), кэши, базы данных |
| `/usr` | Пользовательские программы: бинарники (`/usr/bin`), библиотеки (`/usr/lib`) |
| `/home` | Домашние директории пользователей (`/home/user`) |
| `/root` | Домашняя директория root |
| `/tmp` | Временные файлы (очищается при перезагрузке, sticky bit) |
| `/proc` | Виртуальная ФС: информация о процессах и ядре в реальном времени |
| `/sys` | Виртуальная ФС: информация об устройствах и ядре |
| `/dev` | Файлы устройств (`/dev/sda` — диск, `/dev/null`, `/dev/random`) |
| `/bin` | Основные бинарники (ls, cat, cp) — в современных системах симлинк на `/usr/bin` |
| `/sbin` | Системные бинарники для root (mount, fsck) |
| `/lib` | Разделяемые библиотеки для бинарников из /bin и /sbin |
| `/opt` | Сторонние приложения, установленные вручную |
| `/mnt`, `/media` | Точки монтирования внешних устройств |

### /proc — полезные файлы

```bash
cat /proc/cpuinfo          # информация о CPU
cat /proc/meminfo          # информация о памяти
cat /proc/1234/status      # статус процесса с PID 1234
cat /proc/1234/maps        # карта памяти процесса
ls /proc/1234/fd/          # открытые файловые дескрипторы процесса
```

### Абсолютный vs относительный путь

```bash
/home/user/file.txt    # абсолютный — от корня
./file.txt             # относительный — от текущей директории
../dir/file.txt        # на уровень вверх
~/.bashrc              # ~ = домашняя директория текущего пользователя
```
