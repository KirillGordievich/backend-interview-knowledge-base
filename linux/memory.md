# Linux — Память

## Виртуальная память

Каждый процесс видит собственное виртуальное адресное пространство (64-битная система: ~128 ТБ). Ядро транслирует виртуальные адреса в физические через таблицы страниц (page tables).

**Зачем:**
- Изоляция процессов — процесс не может напрямую обратиться к памяти другого
- Адресное пространство больше физической RAM (с помощью swap)
- Разделяемые библиотеки — один физический блок mapped в несколько процессов

```bash
cat /proc/meminfo          # информация о физической памяти
cat /proc/1234/maps        # карта виртуального адресного пространства процесса
free -h                    # сводка: total/used/free/cached
```

## Страницы (Pages) и Page Fault

**Страница** — минимальная единица управления памятью, обычно 4 КБ.

**Page fault** — обращение к виртуальному адресу, которого нет в физической RAM:
1. Minor page fault — страница есть в памяти, но не замаплена (например, разделяемая библиотека). Ядро добавляет запись в таблицу страниц. Быстро.
2. Major page fault — страницы нет в RAM, нужно загрузить с диска (из swap или файла). Медленно.

```bash
# Статистика page faults процесса
cat /proc/1234/stat | awk '{print "minor:", $10, "major:", $12}'
```

## Swap

Раздел или файл на диске, используемый как расширение RAM. Когда физическая память заканчивается, ядро выгружает (свопирует) редко используемые страницы на диск.

```bash
swapon --show          # информация о swap
free -h                # использование RAM и swap

# Временно отключить swap
swapoff -a
# Включить
swapon -a
```

**Swappiness** — параметр ядра (0–100), как агрессивно использовать swap:
- `0` — swap только при крайней необходимости
- `60` — значение по умолчанию
- `100` — swap активно

```bash
cat /proc/sys/vm/swappiness
sysctl vm.swappiness=10   # временно изменить
```

## mmap

`mmap` — системный вызов, отображающий файл или устройство в виртуальное адресное пространство процесса. Доступ к файлу как к массиву в памяти.

**Применения:**
- Разделяемые библиотеки (`.so`) загружаются через mmap
- Межпроцессная коммуникация (shared memory)
- Работа с большими файлами без загрузки в RAM
- `sqlite`, PostgreSQL используют mmap для файлов БД

```python
import mmap

with open('bigfile.bin', 'rb') as f:
    mm = mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ)
    data = mm[1000:2000]   # читать фрагмент без загрузки всего файла
    mm.close()
```

## OOM Killer

Когда физическая память + swap исчерпаны, ядро запускает OOM Killer (Out Of Memory Killer) — он выбирает и убивает процесс, чтобы освободить память.

**Как выбирается жертва:** по баллу `oom_score` — чем больше потребляет памяти и чем менее важен процесс, тем выше балл.

```bash
# Посмотреть oom_score процессов
cat /proc/1234/oom_score

# Защитить процесс от OOM Killer (только root)
echo -17 > /proc/1234/oom_adj       # старый способ
echo -1000 > /proc/1234/oom_score_adj  # новый

# Найти записи OOM в логах
dmesg | grep -i "out of memory"
journalctl | grep -i oom
```

**Почему приложение получило SIGKILL без причины?** — скорее всего OOM Killer. Проверять: `dmesg | grep oom`.

## Команды диагностики памяти

```bash
free -h                        # общая сводка RAM/swap
vmstat 1 5                     # 5 снимков статистики каждую секунду
cat /proc/meminfo              # детальная информация
ps aux --sort=-%mem | head     # процессы по потреблению памяти

# Утечки памяти в Python
import tracemalloc
tracemalloc.start()
# ... код ...
snapshot = tracemalloc.take_snapshot()
for stat in snapshot.statistics('lineno')[:10]:
    print(stat)
```
